---
title: "Response schema"
---

Successful responses contain data and meta. Download the OpenAPI document for the complete schemas and operation-specific response shapes.

## Identity and provenance

A listing ID identifies an account-owned source observation. Native source IDs remain opaque. Property identity is separate and remains null when no reliable mapping exists. Preserve the source URL and observation timestamp; neither proves present-day availability.

## Money, area and unknown values

Money preserves decimal-string amount, currency, kind and period. Areas preserve numeric value, unit and basis. Do not mix square feet and square metres or infer a measurement basis. Null means unknown, never zero. A property’s condition is not its listing availability status.

## History and media

History is source-reported asking-price information where supplied. It is not a certified transaction record or title history. Media responses can be empty if the upstream observation provides no valid URLs. Do not fabricate source assets.

## Response metadata

meta.request_id supports tracing. Preserve schema_version, generated_at, completeness, source outcomes, warnings and pagination. X-Credits-Used reports the credits charged for this request; an idempotent replay reports zero even though it repeats the original body.

```bash
curl https://realtycrawl.dev/v1/openapi.json
```

## Rich source detail

Zillow detail preserves supported facts, tax history, schools, nearby homes and embedded professional attribution under extensions.zillow. Dedicated section routes read the same account-owned observation for 1 credit. Rightmove retains supported floor plans, tenure, costs and stations; idealista retains explicit amenities and parking. Missing data remains unknown. Documentation-backed features carry DOCUMENTED_SOURCE_BETA warnings.

Across supported listing sources, the facts route also returns explicit normalized search or detail property values with original source identity. New source facts, school and attribution sections are documentation/offline-test backed. Bulk saved reads retain the same public data as each individual operation, rather than returning internal storage objects.

## Projection and export

Use fields and format query parameters on data operations. Fields are comma-separated paths relative to each data item; numeric array indexes use media[0].url. Up to 32 paths are accepted. JSON keeps data and meta; CSV/NDJSON export data records with request, row-count and charged-credit headers. Errors stay JSON. Response options do not change source input, billing or idempotency; replays can use another format without a source call. POST bodies contain only operation parameters.

```bash
curl "https://realtycrawl.dev/v1/listings/LISTING_ID?fields=id,price,property.address&format=csv" -H "Authorization: Bearer $REALTYCRAWL_API_KEY" -H "X-Max-Credits: 1"
```
